Lesson 3

Your First CSS: Paint the Skeleton

Mission: Build D3 data visualizations for your portfolio & to impress your company  ·  Course step: HTML → CSS → JS → D3 → React

Why this lesson

You'll learn one skill here: writing a CSS rule that targets an element by its tag name. You'll use that skill to color each landmark on your page, so the page's structure shows up as blocks on the screen.

Why this matters for D3: in every chart you build, you'll write CSS rules like rect { fill: steelblue; } or .axis text { font-size: 12px; }. These work the same way as the rules in this lesson, just with different element names.

1 · The house analogy

Last session the "letter" analogy had a word collision: we said "letter body" for <main>, but HTML already has a tag called <body>. Let's use a house instead.

HouseHTMLRule
Paperwork in the mailbox (the deed, the address)<head>Not visible. Only one.
The whole house<body>Only one. Every visible room is inside it.
Front porch (with the sign and the doorbell)<header> > <nav>A room in the house
Living room (where life happens)<main> > <article>A room in the house
Back yard<footer>A room in the house, not inside the living room

So <body> has three children, and they sit side by side as siblings: porch, living room, back yard. You can't open a second house partway down the hall, and the back yard isn't inside the living room. (MDN: Structuring documents)

2 · Anatomy of a CSS rule

header { background: lightblue; }
Selector: which elements Property: what to change Value: change it to what

Think of the selector as the address on a work order ("To: every porch"), and the declaration (property: value;) as the instruction ("paint it light blue"). One rule can hold many declarations inside the { }, and each one ends with ;. (MDN: What is CSS?)

Watch out: you've mixed up brace styles before ({{ width=300px). CSS uses one pair of braces, a colon between property and value, and no =. HTML attributes use =, and CSS uses :.
